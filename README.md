# Мангал: OpenFOAM v2606, 350 м³/ч

## Единая команда проекта

Все этапы доступны через `./mangal`. Запуск из любого рабочего каталога:
скрипт сам переходит в каталог проекта и загружает OpenFOAM только для
этапов, которым он нужен. `preview`, `status`, справка и `--dry-run`
работают без OpenFOAM.

```bash
./mangal --help
./mangal status

# Новый полный прогон: расчёт, геометрический preview, отверстия, visualization
# Сетка строится автоматически, если отсутствует или устарела.
./mangal all --iterations 200

# Продолжить сохранённый расчёт и затем обновить все экспорты
./mangal all --resume --iterations 300

# Сначала посмотреть команды, без запуска или изменения файлов
./mangal all --resume --iterations 300 --dry-run

# Отдельные этапы
./mangal mesh --coarse
./mangal run --cold --iterations 30
./mangal resume --iterations 300
./mangal preview
./mangal visualize
./mangal visualize --cold
./mangal audit
./mangal report
./mangal check
```

`--iterations` — общая конечная итерация SIMPLE. `run` и `all` без
`--resume` создают новый прогон с сохранением прежнего case в истории;
`resume` продолжает тепловой расчёт. Для полного холодного цикла:
`./mangal all --cold --iterations 30`.

MPI по умолчанию — `nproc`. Можно добавить `--parallel 4` либо
`--parallel 1` для последовательного выполнения. Для принудительной
перестройки сетки перед новым полным прогоном есть `all --rebuild-mesh`.
Перестройка несовместима с возобновлением старого расчёта.

`all` выполняет этапы последовательно и останавливается при первой ошибке.
`preview` собирает `preview/mangal.obj` и материалы. `visualize` собирает
HTML, OBJ/MTL, VTK/ParaView и компактный архив визуализации по сохранённым
полям; CFD-решатель при этом не запускается. Архив исходников не создаётся.
Единственная точка входа — `./mangal`; Python-модули в `scripts/` выполняют отдельные этапы.


Текущий заданный расход вентилятора — **350 м³/ч**. Вентилятор расположен
на верхнем конце трубы Ø200. Расход вводится в м³/ч в `geometry/parameters.json`
(`physics.exhaust_m3_h`); генератор переводит его в м³/с для OpenFOAM.
Параметр 4000 Вт относится к нагреву углями.

Проверен **холодный проход без нагрева**: `simpleFoam`, RANS kOmegaSST,
30 итераций. Максимальная скорость 3,517 м/с. Это предварительное поле,
строгая нелинейная сходимость ещё не достигнута.


## Расчёт с углями

Добавлен слой углей 50 мм: условный размер куска 30 мм, пустоты 45%.
Это допущения. В CFD слой задаёт сопротивление Darcy–Forchheimer; 4 кВт
передаются воздуху в слое 30 мм над его поверхностью. Дно адиабатическое,
повторного нагрева на нём нет. В OBJ показаны 624 условных куска; отдельные
куски не разрешаются CFD-сеткой. Химия горения и температура твёрдой фазы
не рассчитываются.

```bash
./mangal run --iterations 100
./mangal visualize
# продолжить с последнего сохранённого поля:
./mangal resume --iterations 200
```

При включённом `charcoal.enabled` запуск использует отдельный case
`runs/charcoal/`. Совпадающее холодное начальное поле готовится автоматически,
если отсутствует. Нагрев плавно включается за 40 итераций; с 83-й итерации
уравнение энергии решается без дополнительной релаксации. Это численный
разгон SIMPLE, а не модель физического времени розжига.

Для прежней модели без шампуров проверен проход из **100 итераций**: расход **350 м³/ч**, средняя
температура выхода **51,4 °C**, вынос явного тепла вытяжкой **3,29 кВт**.
Массовый дисбаланс **0,023%**, невязка баланса явного тепла **6,7%**.
**Строгая сходимость ещё не достигнута; результат предварительный.**

- `preview/mangal.obj`: модель с кусками угля.
- `visualization/charcoal/charcoal-flow.obj` и `.mtl`: угли и тёплые линии тока
  для Blender, окраска по температуре газа.
- `visualization/charcoal/charcoal-flow.html`: 3D-поля температуры и скорости.
- `visualization/charcoal/charcoal-preview.zip`: компактный комплект OBJ/HTML/VTK.
- `visualization/charcoal/charcoal-view.vtm`: сборка для ParaView.
- `runs/charcoal/results/REPORT.md`: баланс и ограничения.

Слой сопротивления и зона нагрева выбраны по центрам ячеек. На текущей coarse-сетке
их объёмы отличаются от геометрических; необходима проверка с локальным
уточнением. Суммарный источник нормируется на фактический объём и остаётся 4 кВт.
Числа выноса тепла не являются эффективностью улавливания дыма.

## Посмотреть холодный поток

- `visualization/cold/cold-flow.obj` + `cold-flow.mtl`: геометрия и 36 линий тока
  со стрелками для Blender, полностью офлайн. Размеры — метры.
- `visualization/cold/cold-flow.html`: 3D-просмотр на VTK.js, сечения,
  прозрачность стенок и настройка цветовой шкалы. Для загрузки VTK.js нужен интернет.
- `visualization/cold/cold-view.vtm`: компактный набор для ParaView, со всеми
  соседними каталогами `geometry/`, `sections/`, `streamlines/`.
- `visualization/cold/VTK/isothermal_30.vtm`: полный объём и границы с U и p,
  около 339 МБ. Выгружен штатной `foamToVTK` и не требует OpenFOAM-reader.
- `visualization/cold/cold-preview.zip`: компактный архив визуализации,
  без полной объёмной сетки.

Подробности импорта и цветовых шкал — `visualization/cold/README.md`.
Скорость измеряется в м/с, расход — в м³/ч. p в холодном `simpleFoam` —
кинематическое давление, м²/с². Линии тока относятся к холодному воздуху;
по ним нельзя определить улавливание горячего дыма.

## Запуск

Нужны Bash, Python 3 и OpenCFD OpenFOAM v2606. Дополнительные Python-пакеты
не требуются. На macOS автоматически используется смонтированный том
`/Volumes/OpenFOAM-v2606`. На Linux загрузите своё окружение OpenFOAM
или задайте `OPENFOAM_BASHRC=/path/to/etc/bashrc`.

```bash
./mangal mesh --coarse
./mangal run --cold --iterations 30
./mangal visualize --cold
```

`mangal run --cold` сам перестраивает отсутствующую/устаревшую сетку. Без
`--coarse` фоновая сетка мельче; для первого запуска используйте `--coarse`.
`--iterations` задаёт максимальное число итераций SIMPLE, а не секунды.
Увеличение числа итераций само по себе не доказывает сходимость.

Холодный case находится в `validation/isothermal/`, лог решателя —
`validation/isothermal/logs/simpleFoam.log`. Основной case сохраняет
настройки `buoyantSimpleFoam` для теплового расчёта.

Ранние тепловые диагностические проходы не прошли проверку устойчивости и
не использованы в текущих полях. Для слоя углей применяется холодная
инициализация, отдельная пористая зона, распределённое тепло над слоем и
плавный численный разгон. Текущий путь `mangal run` с углями проверен до 100 итераций,
но для инженерных выводов нужны сходимость и дальнейшее исследование сетки.

## Если запуск кажется зависшим

Теперь скрипты показывают название этапа, путь к логу, время работы и последнюю
строку каждые 15 секунд. Итерации решателя видны в терминале. В текущем
последовательном запуске построение сетки занимало около 6 минут, холодный
проход из 30 итераций — около 5 минут. Нужен запас оперативной памяти в несколько ГБ.

Скрипты используют общую файловую блокировку: второй запуск в том же каталоге
завершится с понятным сообщением, не меняя сетку. Ctrl+C останавливает дочерний
процесс и освобождает блокировку. Это поведение проверено.

```bash
tail -f logs/snappyHexMesh.log
tail -f validation/isothermal/logs/simpleFoam.log
```

Старые логи сохраняются в `logs/history/`; предыдущий основной `postProcessing`
перемещается в `validation/history/` перед повторным тепловым расчётом.

В macOS-сборке встретилась ошибка повторного чтения координат порядка 1e−311 м.
После snapping скрипт `normalize_mesh.py` заменяет только компоненты
|x| ≤ 1e−300 м нулями, сохраняя исходный файл в
`validation/mesh-io/points-before-normalization.gz`. Это устраняет ошибку
`Bad token - could not get scalar value`, не меняя размеры модели.

## Сетка и ограничения

Предыдущая coarse-сетка без шампуров: 2 082 238 ячеек, одна связная область воздуха.
`checkMesh -allTopology -meshQuality` — Mesh OK. Максимальная
неортогональность 51,98°, скошенность 3,8155. Отрицательных объёмов и
недопустимых граней по заданным ограничениям качества нет.

Расширенная проверка `-allGeometry` отмечает 77 811 вогнутых ячеек по плоскостям
граней. Это замечание сохраняется в `logs/checkMesh-extended.log` и явно
показывается валидатором. Для инженерных выводов нужны дальнейшая проверка
качества, независимость от сетки и внешних границ, сходимость невязок и балансов.

Постановка соответствует спокойному окружающему воздуху 293,15 K, без ветра.
Реальная характеристика вентилятора не задана: на выходе принудительно поддерживается
расход 350 м³/ч. Горение, CO, частицы дыма и эффективность их захвата не рассчитываются.

Исходная история постановки сохранена в `CONTEXT.md`.

## Параллельные запуски

`mangal mesh`, `mangal run`, `mangal check` и `mangal visualize` по умолчанию используют
`parallel=nproc`: число MPI-процессов равно результату `nproc` (на текущем Mac — 8).
Поддерживающие MPI этапы выполняются через `mpirun`: snappyHexMesh, topoSet,
createPatch, checkMesh, решатели, postProcess и foamToVTK. Разбиение Scotch
и сборка результатов выполняются автоматически. blockMesh, surfaceCheck,
генерация Python, decomposePar и reconstructPar остаются последовательными.

```bash
./mangal mesh --coarse
./mangal run --cold --iterations 30
./mangal run --iterations 100
./mangal visualize
# Явное ограничение числа процессов для любого из этих скриптов:
./mangal run --parallel 4 --resume --iterations 200
# Намеренный последовательный запуск:
./mangal visualize --parallel 1
```

Число процессов не означает такое же ускорение: расход памяти и накладные
расходы MPI возрастают. Перед изменением case проверяется возможность запуска
MPI. При ошибке нет скрытого переключения на последовательный расчёт.
После включения сетевого доступа агент успешно запускает MPI на 8 процессах.
Проверен параллельный `checkMesh` на отдельной тестовой сетке. При запрете
локальных сокетов `bind()` завершается ошибкой до изменения case. Старые сетки сохраняются в `validation/history/polyMesh-*`, ссылки
исторических case переводятся на сохранённую сетку.

## Шампуры и отверстия

Добавлены 10 круглых шампуров Ø6 мм, по 6 округлых кусков мяса Ø45 мм.
Размеры — допущения, положение вдоль глубины чаши, ось на Z=163 мм.
Мясо и стержни — непроницаемые адиабатические стенки с noSlip;

образуют замкнутую объединённую поверхность без внутренних пересечений.
OBJ: `preview/mangal.obj`; служебная CFD-поверхность: `skewers.stl`.

Восемь отверстий остаются открытыми, без назначенного расхода. Локальный
уровень сетки 6: при `--coarse` шаг 1,25 мм (16 ячеек на Ø20 мм).
Слой углей и нагрева уточнён до уровня 4 (5 мм). Поток определяется
решением, основной приток также может поступать через открытый верх чаши.
Проверка расходов: `python3 scripts/audit_holes.py --parallel 1`
после теплового расчёта; знак плюс соответствует притоку в чашу.

## Архив исходников и Git

`mangal-v2606-source.zip` — снимок проекта для передачи или распаковки
на другом компьютере. Для запуска из Git он не нужен и не обновляется
автоматически; рабочие файлы репозитория могут быть новее архива.

`.gitignore` исключает расчётные сетки, MPI-разбиения, результаты и логи,
проверочные case, экспортированные OBJ/VTK/HTML и архивы. Исходные поля `0/`,
параметры `geometry/parameters.json`, словари `system/`, физические настройки
`constant/` и скрипты остаются исходниками проекта. Правила не удаляют файлы
с диска и не убирают автоматически файлы, уже добавленные в индекс Git.

На macOS ошибка чтения subnormal-чисел возможна также в сохранённых полях
(например, `phi`). Перед MPI-разбиением и сборкой результатов обвязка заменяет
значения с модулем ≤1e−300 нулём; обычные значения остаются неизменными.
Оригиналы сохраняются в `validation/field-io/` соответствующего case.

## Перерасчёт с шампурами, 120 итераций

Новая сетка: 2 820 562 ячейки, одна связная область; обязательный checkMesh —
Mesh OK. Расширенная геометрическая проверка отмечает 102 104 вогнутые
полигональные ячейки; независимость от сетки не установлена.

Холодная инициализация выполнена 30 итераций. Тепловой проход продолжен
с сохранённой итерации 40 до 120 на 8 MPI-процессах. Расход 350 м³/ч,
источник 4 кВт, средняя температура выхода 58,40 °C, массовый дисбаланс
0,0082%. Вынос явного тепла вытяжкой 3918,5 Вт, открытыми границами 67,5 Вт;
невязка этого конвективного баланса 0,35%. Это не полный баланс всех видов
энергии и не эффективность захвата дыма. Строгая сходимость SIMPLE не достигнута.

Сечения через середину толщины стенок подтверждают восемь открытых проходов:
площадь каждого около 99,42% номинальной. Приток через отверстия суммарно
4,48 м³/ч: спереди по 0,573–0,647 м³/ч, сзади по 0,449–0,573 м³/ч.
Основная часть воздуха поступает другими путями, в том числе через открытый
верх чаши. Подробные значения: `runs/charcoal/results/holes.json`.

При прерывании MPI более новый checkpoint может остаться только в
`processor*/`. Возобновление сначала проверяет согласованность времени,
наличие основных полей и прежнюю сетку, нормализует subnormal-значения и
собирает этот checkpoint в общий case. Затем расчёт продолжается с него.
Новые распределённые результаты не удаляются через `decomposePar -force`
без предварительного восстановления; при неоднозначном состоянии запуск
останавливается с диагностикой.

## Проверка Python-кода

Линтер — Ruff, настройки в `pyproject.toml`. Проверяются Python-файлы
`scripts/` и `tests/`: ошибки Pyflakes, базовые ошибки pycodestyle и порядок
импортов. Для тестов разрешён импорт модулей после настройки `sys.path`.

```bash
ruff check .            # только проверка, без OpenFOAM
ruff check . --fix      # безопасные автоматические исправления
ruff format scripts tests
python3 -m unittest discover -s tests -v
```

Ruff нужен только для разработки. Если он не установлен:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

Версия Ruff закреплена в `requirements-dev.txt`; `.ruff_cache/` исключён
из Git. Настройки линтера ориентированы на синтаксис Python 3.12+.

## Сравнение зазора и расхода

```bash
./mangal compare --dry-run
./mangal compare                 # три новых прогона, MPI = nproc
```

Сравниваются 50 см / 350 м³/ч (снимок базового результата 200),
50 см / 600 м³/ч, 35 см / 350 м³/ч и 35 см / 600 м³/ч.
Каждый новый вариант: холодная инициализация 30 итераций и тепловой проход
до 200. Проекты изолированы в `runs/comparisons/hood-gap-fan/`.
Повторный запуск пропускает варианты с `COMPLETED.json`. Итоговые файлы:
`REPORT.md`, `comparison.csv`, `comparison.json`, `comparison.html`.
Базовые исходные поля и визуализация не перезаписываются.

В активной конфигурации расход задаётся только в м³/ч:
`physics.exhaust_m3_h` и `fan.flow_m3_h`. OpenFOAM получает м³/с
(деление на 3600). Старые case с CFM читаются с преобразованием;
их исходные параметры и результаты не мигрируются на месте.
Сравнение предварительное, без пассивной примеси и без оценки процента
улавливания дыма. Реальный вентилятор должен обеспечить заданный расход
при сопротивлении установленной системы.

`runs/comparisons/hood-gap-fan/comparison.html` содержит четыре 3D-окна
в одном VTK.js canvas. Камера общая: вращение, перемещение и масштабирование
любого окна синхронно меняют остальные. Общая панель управляет полем
температуры/скорости, цветовой шкалой, выбором одного из трёх рассчитанных
сечений, группами линий, видимостью геометрии и прозрачностью стенок.
Кнопки ракурсов действуют на все варианты. Плоскости сечений заданы в
одинаковых мировых координатах; произвольное перемещение среза не добавлено.

Повторная команда `./mangal compare` при завершённых вариантах обновляет
страницу и отчёт, не запуская CFD заново. Данные встроены в HTML;
для загрузки VTK.js с CDN требуется интернет. Размер страницы около 50 МБ.

Проверка обработчиков общих настроек без GPU:

```bash
node tests/test_comparison_controls.cjs
```

Браузерный тест в среде агента macOS блокируется запретом MachPortRendezvous;
проверены синтаксис JavaScript, обработчики настроек и данные четырёх полей.
